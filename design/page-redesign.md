状态：当前正式设计基线，2026-09-15。覆盖当前 7 个原生页面，以及家庭详情内部视图、弹层与异常流程。原生页面已按此基线更新，范围与验证限制见 [落地记录](../docs/miniprogram/page-redesign.md)；未部署。

- [可点击原型](index.html)
- [样式与视觉 tokens](styles.css)
- [原型交互脚本](prototype.js)
- 业务依据：[首版需求](../docs/REQUIREMENTS.md)、[当前范围](../docs/SCOPE.md)。本次设计按用户确认取消个人事项：所有事项必须属于家庭，无家庭时先创建或加入。客户端入口已同步家庭归属规则；历史数据未自动迁移，其他规则继续沿用现有需求。
- 用户已确认用此版本替换旧设计。旧主稿、流程稿及家庭导航稿已移除；后续页面实现以本规范和当前原型为准。原生同步状态以落地记录为准。

## 1. 设计目标与方向

**家庭日常清单：看清一件事，知道为谁做，记录这一次。**

当前页面代码中的主要问题：短操作与复杂设置同处长弹层；权限矩阵在窄屏上需要同时理解三类授权；完成记录与周期管理距离近；家庭成员日常信息和退出、转交入口的层次较弱。以上判断基于 WXML、样式、事件与业务文档，不表示本次观察过旧版真机界面。

本次采用一个方向：保留蓝紫品牌色，收敛大面积装饰；事项采用分组白色清单、细分隔线；家人使用带称呼的柔色头像标记；固定主按钮一屏只承担一个主要动作。首页、进度页保留少量「家 / 伴」手写印记作为识别元素，字体回退不影响信息理解。信息分组来自真实角色，不使用排名或激励积分。

### 信息顺序

| 页面 | 第一眼要看到 | 接下来 | 固定操作 |
| --- | --- | --- | --- |
| 首页 | 今天与全局到时提醒 | 家庭、日期、事项分组 | 记一件事；多选时替换为批量操作 |
| 详情 | 事项、家庭、执行对象、本次状态 | 安排、真实记录、整个周期 | 记录本次完成 / 撤销本次记录 |
| 编辑 | 标题和备注 | 为谁 → 时间 → 谁一起照应 | 保存这份安排 |
| 家庭 | 本机资料、我的家庭 | 创建 / 加入、进度、回收站 | 原生双 tab |
| 家庭详情（内部视图） | 家庭和拥有人 | 成员、邀请、无账号成员 | 管理危险操作放正文底部 |
| 邀请 | 家庭与邀请有效性 | 发出 / 接收各自操作 | 原生分享或主动接受 |
| 进度 | 家庭与日期 | 执行对象、完成/待完成/跳过 | 管理家庭作为次操作 |
| 回收站 | 所属家庭、删除事项 | 恢复影响 | 每项独立恢复 |

## 2. 页面合同与保留入口

以 `miniprogram/app.json` 的实际路由为准，旧业务文档中的建议路径不直接采用。下列所有能力必须在原生落地时保留；原型只对部分做本地数据联动，其余展示关键确认页。

| 原生路由 / 来源 | 既有入口和合同 | 新位置与处理 |
| --- | --- | --- |
| `pages/home/index` | 全家庭聚合、家庭筛选、今天/明天/未安排/已超时/指定日期、显示完成、下拉刷新 | 日期栏紧贴筛选；单组清单；保留当前日期、家庭和返回滚动位置 |
| 首页事项卡片 | `OccurrenceRef` 对应独立次数，完成/撤销、canRecord、管理多选 | 左侧 44px 点击区记录，正文进详情；只读圈显示横线和说明；多选是独立模式 |
| 首页提醒 | 全局提醒、已读、收起、查看已收起 | 顶部单行摘要打开提醒弹层；每项有查看和收起；原生默认隐藏已收起，提供显式切换 |
| 首页快速新增 | 连续保存、家庭偏好、标题/日期/时刻/执行对象/重复/备注/可见人、草稿、转完整编辑 | 精简层显示标题、日期、归属；“更多安排”带全部输入进编辑页，其余能力仍可到达 |
| 首页批量 | 最多 20 个不同事项、按家庭追加、逐项结果、待确认续办、失败重试 | 多选 → 按家庭配置 → 影响摘要 → 结果；不把多个周期次数重复计为多个事项 |
| 首页异常恢复 | 待确认写入提示、主动重试 | 提示放当前列表上方；标明操作摘要；不自动重放 |
| `pages/detail/index` | `id`、可选编码后的 `occurrence`；参数与 taskId 校验 | 每次操作固定绑定原事项与原次数；换筛选不改变操作目标 |
| 详情安排与记录 | task.get / history、执行对象、查看/代记名单、实际完成和系统记录时间、记录人 | 主状态卡仅展示本次；完整记录单独区块；可见名单和本人提醒在设置中 |
| 详情系列管理 | pause/resume/stop、delete、reminder preference、补记/跳过/撤销 | 周期管理卡与本次分开；删除整体放“更多”；停止不可逆状态单独说明 |
| `pages/editor/index` | `id`、`share=1`、`familyId`、`seed=1`、`draft=quick` | 保留参数与输入转交；共享模式直接定位权限段，其他不允许编辑的段只读 |
| 编辑共享组件 | 内容、执行对象、日程、权限、服务端预览、版本冲突 | 保留字段与所有校验；原矩阵改为每人展开的查看/代记/提醒设置 |
| `pages/families/index` | 列表/详情内部切换、可信家庭选择上下文、tab 切换 | 不新增详情路由；清除上下文回家庭列表，tab 再入规则沿用服务状态 |
| 家庭资料 | `chooseAvatar`、`type=nickname`、本机持久文件及按账号隔离 | 顶部资料行；弹层修改；不将本机昵称代替家庭称呼 |
| 家庭管理 | 创建/更名、真实称呼、虚拟成员新增/更名/停用、邀请、移除/退出/拥有权转交 | 成员行打开管理；底部独立交接区；普通成员只显示本人可执行动作 |
| `pages/invitation/index` | `familyId` 发起；`token` 分享接收；手动口令；主动接受；重复加入 | 两种运行情境，不把原型“发出/接收”评审切换器做成用户必选步骤 |
| 邀请分享回调 | `onShareAppMessage` 保留有效邀请口令；原生 `open-type=share` | 成功生成后主按钮为“分享给微信好友”；接收预览成功后隐藏手动输入；失败再出现 |
| `pages/progress/index` | 家庭/日期/执行对象筛选、完整扫描、虚拟身份、不排名 | 紧凑筛选 + 按人统计卡；正文只展示可见项，不新增未确认的进度详情路由 |
| `pages/recycle/index` | 全部或原有家庭范围上下文、可管理列表、restore | 保留 scopedFamilyId 约束；恢复前确认，失败留卡；无永久删除 |

页面仍通过 services 访问 API，写请求保留 requestId、expectedVersion 和可信账号上下文。读取状态及缓存仍由现有页面/服务控制；不因设计变更增加未授权的接口、订阅通知、离线队列或自动提交。

## 3. 视觉规范

### 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| brand / brand-dark | `#5059AD` / `#3F478F` | 主按钮、当前选中；在现蓝紫色系内微调 |
| canvas / paper | `#F5F6FA` / `#FFFFFF` | 页面 / 白色清单与表单 |
| ink / muted | `#292B40` / `#696C80` | 正文 / 辅助文字 |
| line / soft | `#E4E6EF` / `#ECEEFA` | 分隔线 / 提示与次按钮 |
| green / green-soft | `#376A55` / `#EAF3EE` | 完成状态，必须配“已完成”和勾选 |
| amber / amber-soft | `#865B20` / `#FFF2DB` | 已到时间、计划日期已过、重要影响 |
| danger | `#A43D48` | 移除/删除/退出，配动作名称和确认 |

原生实施统一更新 tokens 和组件适配层，不在各页散写色值。此次仅原型使用新值，旧 tokens 未改。

### 尺寸和字体

- 基准设计宽度 390 CSS px；原生 750rpx 体系按相对宽度换算，44px 触控下限用实际设备验收，不能只机械写 88rpx。
- 页面边距 18px；分组间距 16/24px；卡内边距 18px；细分隔线 1px；清单行至少 86px，标题允许完整换行。
- 卡片圆角 18px；按钮 12px；弹层上角 24px。短说明可留白，避免同一层堆叠多层边框。
- 正文 PingFang SC / 系统无衬线 15–16px、行高 1.55；页面标题 26px/650；事项详情 28px/650；章节 18px；辅助 12–13px/1.8。11px 仅用紧凑标签，不承载唯一的授权或危险操作说明。
- 手写字体 Kaiti SC / STKaiti 仅用于识别印记与评审封面；无该字体时回退 serif。数字使用系统等宽数字特性，不下载字体。
- 图标正式落地复用已有 SVG 线性图标，20–24px；原型的 Unicode 图形为占位，不作为最终 tabBar 资源。
- 实际原生 nav/status 高度由现有 navigationMetrics 决定；保留微信胶囊区域。底部仍为“首页 / 家庭”原生 tabBar，不新增第三个 tab。

## 4. 逐页交互

### 首页与到时提醒

```text
日期问候                    家庭印记
全局到时提醒 → 提醒弹层
[全部家庭 ▼]                 多选
[今天][明天][未安排][已超时][日期]
当前范围已完成 / 应做        显示已完成
我来做 → 事项清单
帮家人 → 事项清单
关心一下 → 只读清单
[              ＋ 记一件事             ]
[          首页          家庭          ]
```

- 事项标题优先；下一行标明执行对象和家庭；再一行显示时刻/周期及时间提示。每个事项必须有家庭归属。家庭同名时仍按真实 ID 区分。
- 已超时只查询早于今天的未完成事项，卡片显示原计划日期；没有总完成率或显示完成开关。今天已到具体时刻仍留在今天。
- 默认隐藏已完成。成功完成后保留列表、局部“刷新中…”蒙层，读取完再移除；完成/撤销失败保留原数据。蒙层不覆盖新增按钮，刷新中可以填写，提交等待当前写入结束。
- 下拉、30 秒前台刷新、缓存有效性、快速切换隔离沿用现有实现；不因重设计预加载全部日期。
- 提醒“查看”记录本人已读后打开对应次数；“收起提示”只修改本人提示。全局提醒不跟随家庭筛选；下一次周期提示独立。
- 无日期、无具体时刻不显示到时预警；提醒关闭和已收起不影响清单中的到期提示。

### 快速新增、草稿与完整编辑

1. 点击“记一件事”，半屏弹层展开，标题输入获得焦点。标题为唯一必填项；日期可以未安排。
2. 始终显示归属。按账号与环境记住上次选择；无偏好才沿用首页家庭筛选，失效家庭要求重新选择有效家庭；无家庭时进入创建/加入引导。新建优先使用有效家庭偏好，明确 familyId/原事项/草稿优先。
3. “保存，再记一件”成功后清标题，保留日期和归属便于连续输入；成功前不清任何字段。复杂周期和家人设置通过“更多安排”带入，不丢备注和已选权限。
4. 关闭有改动的表单展示“保留输入 / 放弃输入 / 继续填写”；仅本地保存成功后关闭。恢复时重新检查权限与版本，说明不会自动提交。
5. 完整编辑顺序：标题/备注 → 家庭/对象 → 日程 → 权限。各段可见，不使用强制多步向导；保存按钮固定。
6. 已有家庭事项不能跨家庭迁移；切换新建归属清除旧家庭名单、重新读取成员；原对象不可用要求重选。

### 时间与周期

- “不重复 / 每天 / 每周”用分段选择，之后显示对应字段。每日/每周必须有开始日期，可选结束日期；每周至少一天；时刻最多 6 个，逐个删除，不重复。
- 无时刻显示“不限定时刻”，不隐式生成午夜；无日期一次性不能留具体时刻。错误紧邻字段，提交滚到第一个错误。
- “查看接下来 3 次安排”调用服务端预览：显示日期、时刻、执行对象；加载中不展示旧预览，失败可重试。预览不是最终落库结果。
- 今天新建的有时刻周期跳过已经过去的时刻；未来次数不能提前记录。修改周期仅影响未来；已有历史的周期不提供转一次性。
- 已完成一次性锁定日期、对象、重复，仅允许修改内容，提供“另建事项”；已跳过先撤销再调整。恢复草稿不能绕过锁定。

### 权限与提醒

- “谁一起照应”摘要默认“仅自己可见”；家庭成员逐人展现。必要可见人说明原因，不提供可取消的假开关。
- 勾选“可以查看”后，再展开“允许代记完成”“接收小程序内提醒”；两者默认不选。每个开关使用完整行 44px 热区。
- 选择真实家人为执行人，说明“将能查看并记录完成，无需接受”；不默认开其提醒或给予编辑权。
- 无账号对象显示“由拥有人管理”，管理人与创建人可见；虚拟人不显示接收提醒开关。
- 取消可见但存在代记/提醒时，确认同时移除这些能力；取消确认不改草稿。保存统一提交，不逐个开关直接写云端。
- 家人自行关闭显示禁用说明，管理人不能勾选；本人自己的提醒独立操作。取消/恢复共享、重新加入或恢复事项不重置本人意愿。
- 共享专用模式仍保留原 share=1 边界，不能把标题、时间、执行对象一起写成新内容。

### 事项详情、记录、历史和周期

- 页面从具体 occurrence 进入，顶部永远是该次执行对象、日期和状态；历史与当前对象不同，分别标注，不用系列现对象覆盖历史。
- 底部“记录小宝完成”明确是代记；完成后呈现“小宝已完成，由奶奶记录”。实际完成时间、系统记录时间、真实操作人和备注完整保留。
- 补记弹层含实际完成时间和可选备注；不允许未来完成时间，其他有效时间范围由契约/领域校验。补记与跳过不同按钮，跳过确认只影响一次。
- 已完成/已跳过主按钮为“撤销这次记录”；未来周期次数只显示安排和说明，不出现可记录控件。撤销成功后重新判断到时提醒。
- 整个周期卡显示进行中/暂停/停止、按日期历史、暂停/继续/停止后续。暂停保留已有待办；继续前显示下一次；停止后不再提供继续。
- 删除整个事项放“更多”底部，明确包括系列、历史暂时隐藏并可恢复；已有历史的周期提供停止后续作为独立选项。
- 只可查看者无完成、编辑、共享、删除按钮；仍能调整本人的提醒。权限变化清理敏感旧内容，回到有权页面。

### 家庭与资料

- 家庭首页资料行显示本机昵称/头像和编辑箭头；未设资料仍可使用应用，不弹强制授权。
- 家庭卡显示名称、我的角色/拥有人、成员标记；角色逐家庭计算。创建家庭与加入家庭为并列次按钮。
- 家庭详情是现页面内部视图；标题、拥有人、成员列表。每个成员显示真实/无账号标记，今日可见进度若失败显示“暂未加载”，不可伪装为零。
- “管理”展开改称呼与有权限的删除入口。普通成员只能改自己的称呼；拥有人可管理其他成员；拥有人的自我删除入口转为转交引导。
- 添加无账号成员只填写称呼；停用确认保留历史和未结束事项，停用后新建选人中隐藏。
- 家人进度和回收站保持可发现的工具行，家庭范围回收延用原范围参数。

### 邀请、退出和交接

- 发起情境：只对拥有人开放生成与撤销；生成后显示有效截止时间、分享、复制口令及邀请列表。生成不会自动分享。
- 接收情境：分享参数 token 自动预览，不自动加入；输入家庭称呼后主动接受。手动加入先口令预览；过期、撤销用不可用提示。有效接收页可转发原口令。
- 分享使用微信原生能力；口令不写普通日志或永久存储，接受未决只在当前进程中主动确认；重启重新预览。
- 退出/移除真实成员：先加载承接人、普通事项数、原私密数量、创建职责数、虚拟事项数；只显示授权范围内的影响，不向未授权者暴露私密标题。
- 预览失败禁用确认，提供重新查看；预览过期/版本冲突必须重新读取，不沿用旧承接人；确认后才失去家庭访问权。
- 拥有人转交只能选择有效真实成员；无承接人引导邀请。转交成功仍是家庭成员，退出另行确认；虚拟事项实际管理归属交接，历史执行对象不变。

### 家人进度

- 筛选顺序：家庭 → 日期 → 执行对象；全家庭摘要不泄露另一个家庭成员信息。
- 卡片显示头像/称呼、身份、已完成/应做分母、待完成、跳过数量和有权查看的事项。进度条仅辅助，数字和文字始终保留。
- 完整读取前隐藏最终统计；部分失败整段显示未完整加载，不展示局部最终总数；重试沿用当前筛选。
- 没有家庭、没有共享安排、没有记录三者分开。“没有记录，不代表没有完成”作为页尾说明。
- 不做排名、积分、催促或“落后”等推断；同名无账号成员按所属家庭和真实 ID 区分。

### 批量与回收站

- 多选只对有管理权限的不同事项可用；已选数 / 20 常驻底部；取消退出多选，不触发任何写入。
- 按原所属家庭分组；不再提供未归属家庭组或批量归属入口。各组选人互不污染，即使同一用户属于多个家庭也分别校验。
- 确认摘要显示每组事项数量、目标家庭、新增可见人；保留原名单，不自动开启代记/提醒，既有家庭事项不迁移。
- 结果逐项显示“成功 / 失败与原因 / 待确认”。待确认时“继续确认本次批量操作”使用原 ID 和全部原参数；终态后“仅重试失败项”用新请求。成功项不重复提交。
- 回收站不提供彻底删除、自动清理或批量恢复。恢复前说明范围；恢复失败保留原卡片；成功移出回收列表。
- 周期恢复为暂停，删除期间不补次数；已停止系列恢复历史后仍不能继续；仅保留当前有效成员权限。

## 5. 共同状态、尺寸与动效

| 状态 | 设计反馈 | 可用动作 |
| --- | --- | --- |
| 首次加载 | 静态骨架 + 正在加载，不闪空内容 | 保留安全导航；禁用依赖数据的写入口 |
| 首次无安排 | 说明当前日期无安排 | 记一件事；已超时态说明历史未完成范围 |
| 首次无家庭 | 所有事项需要归属家庭 | 创建 / 加入，完成前不能新建事项 |
| 读取失败 | 原因及重试，不能变为空状态 | 当前范围重新加载 |
| 部分读取失败 | 说明未完整读取，隐藏最终统计 | 重试受影响范围，不显示“全部完成” |
| 保存中 | 主按钮“保存中…”、不可重复提交 | 保留上下文，不静默关闭弹层 |
| 写入结果未知 | “暂未确认是否保存成功” + 原操作摘要 | 使用原请求主动确认，不新建同一操作 |
| 版本冲突 | 本地输入与最新内容对照，不自动覆盖 | 保留/放弃输入；核对新版本后提交 |
| 无记录权限 | 文字说明；隐藏或禁用记录入口 | 阅读及本人提醒设置 |
| 成员关系失效 | 关闭失效编辑、清理敏感内容 | 返回仍有权的首页/家庭 |
| 表单错误 | 字段旁具体原因 | 首错定位，输入保留 |
| 草稿恢复 | 说明原家庭、目标、日期 | 恢复后重校验 / 放弃；不自动保存 |

- 动效：按钮按下轻微明暗变化；状态完成反馈 120–160ms；半屏进入/退出建议 180–220ms。无循环庆祝、闪烁预警或强制进场动画。减少动态效果时直接切换状态。
- 触摸：最小 44 × 44px；长标题换行、家庭名最多两行；不让省略遮住执行对象和权限说明。校验 320 / 390 / 430px 及大字体。
- 弹层：短操作半屏，长权限和交接支持内部滚动；保存区不被键盘遮挡；关闭由页面统一处理，不用组件自动关闭绕过未决操作保护。
- 微信胶囊、状态栏、tabBar、底部安全区使用原生测量与平台组件。原型仅模拟，不以固定高度替代真机适配。
- 屏幕阅读：所有图标按钮具名，控件有标签，选中和禁用可读；切换只更新相关区域；弹层焦点进入和退出恢复，Web 原型支持 Tab 循环与 Escape。

## 7. 验证与交付

本次只增加设计产物并在设计 README 增加入口。未运行 `npm run check`，因为没有基础架构、契约、构建或原生业务代码变更。

验证结果记录在 [原型验证](VALIDATION.md)。浏览器视觉/交互检查不能替代微信开发者工具、真实云环境、多微信账号及 iOS/Android 真机验收。

建议评审顺序：先首页新增与完成 → 详情/周期 → 编辑/权限 → 家庭/邀请/交接 → 进度/回收 → 左侧异常状态。后续实现需以本规范为新的呈现基线，并保留现有行为测试和 API 合同；本次不自动执行实现或发布节点。

### 清单权限辨识补充

- 可记录事项排在前面，保留「我来做 / 帮家人」分组、白色背景及品牌色完成圆框；不再逐条显示权限标签。
- 只读事项放入「关心家人」分区，通过更大的间距、分隔线、浅灰背景和眼睛图形区分，不显示完成圆框、权限标签或重复说明。
- 区分不只依赖颜色：控件形态和分区同时表达差异，辅助技术仍能读出「仅查看」。正文保持正常对比度。
- 点击只读行进入详情查看进度与记录；不改变完成、编辑或管理权限。批量操作仍依据管理权限判定。
- 日期、家庭筛选与原统计口径不变。

### 家庭列表概览

家庭卡片仅展示家庭名称、本人在家庭中的角色和成员总人数，不展示具体成员姓名、头像或拥有人姓名。具体成员及管理入口在家庭详情中展示；人数包含真实成员与虚拟成员。

家庭卡片采用紧凑两行布局：首行名称与进入箭头，次行成员人数与本人角色，以细分隔线分开。长名称允许换行，人数和角色在窄屏按需换行，避免截断。

家庭列表为空时，同时展示「创建家庭」与「加入家庭」两个直接入口。创建打开家庭名称与本人称呼表单；加入进入邀请口令预览流程。空状态说明先创建或加入家庭再使用事项功能。

### 箭头尺寸与边距

进入箭头统一为 20 × 20 px 图标区域、2 px 线宽，不随辅助文字缩小。下拉选择框箭头同为 20 px，距右边缘 14 px，文字右侧预留 44 px，避免文字与箭头拥挤。原型保留原生 select 的选择和键盘行为，仅调整外观。

### 家庭归属规则调整（用户已确认）

- 整个新设计取消个人事项，首页和回收站不再有个人筛选，快速新增与完整编辑只能选择家庭。仅自己可见仍是家庭内权限设置，不代表无家庭事项。
- 无家庭状态在首页、家庭和编辑入口统一引导创建或加入，隐藏新增与保存事项按钮；切换页面不解除限制。创建或接受邀请后恢复事项入口。
- 示例中原个人事项已归入「我的小家」，仅用于演示。真实历史数据如何迁移尚未确定，不会自动绑定家庭或修改云端数据；实现阶段需明确迁移规则。
