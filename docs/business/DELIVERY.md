# 开发顺序与验收映射

状态：身份、个人及家庭协作、周期、进度与批量追加已实现，七个原生页面已接入；周期相关原生页面已继续补验，详情页编译兼容问题已修复；具体通过项见 [原生验收记录](../verification/native-acceptance/README.md)，双真实账号与真机验收尚待完成。实际 action、存储和验证边界见 [个人待办实现](../technical/PERSONAL.md)、[家庭协作实现](../technical/FAMILY.md) 和 [发布记录](../technical/CLOUD_DEPLOYMENT.md)。下文保留首版完整设计；实际部署及本地/真实验证以发布记录为准，订阅提醒尚未实现。

## 开发顺序

0. **平台接入验证**：锁定 SDK，验证逐请求可信身份及非小程序调用拒绝、文档事务冲突、独立 bundle 与健康分支、业务集合仅服务端访问；证明后再接业务。保持现有 Node/单函数配置，真实环境操作另按授权执行。
1. **身份与契约**：实现可信 Actor、identity.ensure；把 schema 和错误码从蓝图落到 contracts，增加字段及越权输入测试。保持 system.health 兼容。
2. **个人待办闭环**：Task、单次记录、持久化幂等、版本冲突；实现创建/列表/详情/完成/撤销/删除恢复和默认提醒。首次真实写入前完成集合权限和索引验证。
3. **家庭协作**：家庭、邀请接受与撤销、真实/虚拟成员、权限矩阵、多家庭聚合；实现退出及转交的归属解析，不先上线“只能加入不能退出”的半套权限模型。
4. **周期与进度**：独立计划投影、每日/每周/多时刻、暂停恢复停止、补记跳过、跨家庭提醒、可见进度。
5. **批量与联调**：逐项追加、失败重试、真机多账号联调、故障恢复、性能及权限验收。

每一步按 contracts → domain → ports/application → infra → 小程序 services/pages 落地，不让页面直连数据库。业务实现不从浏览器 demo 直接复制状态存储或固定时间；可复用的是视觉 tokens、文案和交互规则。

## 必须通过的行为验收

| 需求场景 | 核心测试 / 可测结果 | 对应模块 |
| --- | --- | --- |
| 周期照护 | 周一/三/五 08:00、20:00；今天 18:30 创建，只安排今天20:00，未来每天各自独立；父母分别记录 | schedule projection、occurrence |
| 快速记事 | 连续新增三项明日事项，没时刻照常保存、提醒设置 true、到时提示不新增；重复请求仅三条 | task.create、idempotency |
| 虚拟人作业 | 妈妈为家庭拥有人，爸爸创建，小宝执行，妈妈实际归属，奶奶操作；四种身份正确且可追溯 | task ownership、audit |
| 默认私密 | 普通新项其他家人不可读；虚拟项只有必要归属/创建人访问；称呼相同不能赋权 | policy |
| 查看与操作 | 只读用户直接构造 record/share 请求失败；取消查看后提醒与代记立即失效 | access transaction |
| 退出交接 | 500 项无需超大事务，退出后拥有人能检索全部承接项；退出者详情/缓存刷新失权；其他家庭不变 | successor resolver、aggregate |
| 拥有权转交 | 转交前并发修改使预览过期；无有效接收人不能退出；虚拟归属更新、历史不变 | family fence |
| 周期例外 | 暂停跨两天后恢复无补出次数；旧已到时/完成不因改时间消失；停后不能继续；跳过减少分母 | segments/controls |
| 提醒状态 | A 收起不影响 B；完成撤下，撤销后重新判断；历史未完成仍可查，家庭筛选不影响提醒 | receipts、reminder.list |
| 多家庭 | 同名事项 ID 独立；不同 scope 部分失败不显示完整总数；旧筛选响应不覆盖新筛选 | aggregate、page generation |
| 批量追加 | 20 项含个人和两个家庭；每项归属/权限一起成功；预算耗尽返回 pending，同ID续跑；全部终态后第7项失败重试只处理它；重复追加去重 | batch transaction |
| 家庭隔离 | A 家拥有人不能通过 taskId/memberId/cursor 读取 B；已撤销邀请并发接受不得加入 | policy、cursor、invite |
| 删除恢复 | 回收只含自己可管理项；恢复不复活已退出成员；周期暂停恢复，不补删除期间次数 | lifecycle |
| 真实家人安排 | 选爸爸保存后立即可见及本人可记录，无需接受；无隐式提醒或管理权 | policy、task.create |
| 执行人变更 | 今日已到时次数保留小宝，未来换另一个孩子；历史进度仍归小宝，旧本人记录权限按各次判定 | schedule subject、progress |
| 编辑边界 | 已完成 once 改日期/重复/执行人失败；未完成可改；有历史周期转 once 失败；改标题备注保留审计 | task.update |
| 本人提醒优先 | A 关闭后 B 勾选返回 INVALID_STATE；并发、重新共享、重新加入、恢复均不绕过；A 主动开启后可提醒 | preference、transaction |
| 转发邀请 | 同一有效邀请两人接受均成功，无审批；撤销后第三人失败，前两人仍为有效成员 | invitation |
| 持久化并发 | 同版本双完成仅一个成功，另一个冲突；写成功响应丢失后同ID重试不重复；重进数据保留 | transaction、idempotency |
| 分页一致性 | 空页但未扫完可继续；签名游标不可跨账号/筛选使用；scope变动失效；分窗口遍历不漏不重，完整前不显示总数 | query session、revision |
| 退出丢响应 | 成功退出/转交后重试原命令能取得最小回执；不泄露旧家庭内容、不重做交接；未知状态重进仍可核实 | idempotency、request manager |
| 时区边界 | 上海23:59/次日00:00、月末、闰日、周日到周一、无时刻与多时刻、起止同日 | Clock、calendar |

单元测试注入 Clock 和仓储；集成测试覆盖事务回滚及幂等结果原子性、权限读写竞争。构建/契约变更执行 `npm run check`。真实 CloudBase 事务能力、索引以及多账号成员权限必须通过预发布环境测试，不能仅用内存 fake 证明。

## 工程验收值

- 每次列表最多31天、每页20条默认/50条上限、批量20项；无静默截断。
- 前台提醒30秒刷新；进入立即刷新；隐藏后无轮询；10秒超时，失败退避5/15/30秒。
- 目标测试数据：10个家庭、每家20真实+20虚拟成员、500事项，其中100个每周6时刻周期。分页首次可见结果目标 p95 ≤2秒（暖调用，预发布同地域），常见当天数据完整总计目标≤5秒；31天密集周期和长期积压单独压测，允许跨调用继续，不承诺统一5秒完成。未达标需优化或明确加载状态，不能删记录冒充达标。冷启动独立记录。
- 列表页、编辑页、弹层在320/390 CSS px无横向溢出，热区≥44px；真机检查键盘、安全区及微信菜单区域。
- 发布前核对SDK/运行时和事务平台约束、迁移可重跑、只服务端可读写业务集合、日志脱敏。不在本次设计补全时部署或新增资源。

## 每个步骤的交付门槛

- 契约：action、输入输出 guard、稳定错误及调用示例同步；拒绝伪造身份和未知字段。
- 领域与用例：注入 Clock/ID，权限、日期、版本及回执用行为测试验证；核心层不依赖 SDK。
- 存储：迁移清单、索引、规则、真实事务回滚及并发验证齐全；单次事务≤80次文档操作。
- 客户端：乱序响应、失权清理、结果未知重试、分页和批量续跑、前后台轮询通过；界面区分未加载与空数据。
- 集成：`npm run check` 通过，自包含函数和小程序共享代码可独立运行；平台与多账号真机结果单独记录。

按步骤交付可测试代码，不等同于对外发布。家庭能力只有邀请、退出、交接、撤权闭环完成后才具备发布条件。
