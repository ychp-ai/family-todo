## 草稿重启问题

此前失败原因已定位到开发工具存储延迟落盘：

| 独立探针 | 写入后立即读回 | CLI 关闭项目并重开 |
| --- | --- | --- |
| 新字符串、对象，约 2 秒后关闭 | 正确 | 两者均丢失 |
| 新字符串、对象，35 秒后关闭 | 正确 | 两者均保留同一唯一标记 |

探针直接使用 `wx.setStorageSync`，不依赖草稿服务。只读检查安装包 `app.asar` 的存储模块，发现最后一次写入后延迟 10 秒保存，后续写入会重置 timer；即时关闭保存钩子未在 Electron 分支注册。没有修改开发工具，也没有在产品中加入等待或私有刷盘调用。当前开发工具即时关闭仍可能丢数据。

以 35 秒等待为明确前提，执行 CLI `close --project <仓库>`、`auto --project <仓库> --auto-port 9420`；App 内存探针消失证明重新启动，而非仅重新建页。验证结果见 [恢复记录](recovery-result.json)：

- 空标题、备注、未完整时刻 `12:` 正确恢复，放弃后清理。
- quick→editor 使用同一草稿 UUID。
- 真实创建成功后人为丢弃响应，首页保留未确认请求。
- 重启确认使用原 requestId 和完整 payload；云端事项 version=1，二次确认不再发写。
- 成功后旧草稿不再恢复，验收事项已移入回收站。

## 页面验收方式

页面在微信原生运行时渲染，API 请求使用真实云环境；输入、按钮处理函数和模态选择由 miniprogram-automator 0.12.1 驱动。截图经过视觉检查。此方式验证页面事件处理、状态、渲染与云端联动，不等于逐个控件的触摸手势、系统 picker 或真机键盘验收。

已通过详情完成/撤销、跳过/撤销、补记实际时间和备注、审计历史；进度在跳过时为 0/0、跳过 1 件，改为完成后为 1/1，分母和执行对象筛选正确；周期暂停/继续、原生删除和回收恢复（恢复为暂停且保留历史）、停止后不能继续。

混合批量选择一件个人事项和一件家庭事项：个人事项成功转入家庭，另一件由真实并发更新触发 `VERSION_CONFLICT`。结果页正确呈现一成功一失败；“仅重试失败项”只提交失败事项，成功事项版本保持不变，重试后全部成功。首轮脚本曾在成员名单加载完成前操作而超时，补上页面就绪等待后重跑通过，未修改业务代码。

无账号成员的创建、改名和停用均通过，停用后展示“已停用”。仅清理本轮新增数据：验收事项已移入回收站，验收虚拟成员已停用；保留既有数据。

另以原生界面点击“查看家人→管理家庭→查看家人”，实际滚动到家庭页底部；添加成员、邀请、转交、退出、创建和加入按钮均完整显示，无重叠或底部裁切，见 [底部按钮截图](family-bottom.png)。此项只检查入口和布局，未执行转交、退出或邀请。
