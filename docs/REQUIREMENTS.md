# 家庭待办提醒首版需求

本文为当前确定的首版产品需求。用户已确认核心规则，并授权采用场景推导及需求检查中的其余建议。多家庭规则取代此前的单家庭限制；成员退出默认交接给家庭拥有人；虚拟人事项实际归属家庭拥有人、展示为对应虚拟人。

已进一步确认：给真实家人安排无需对方接受但须明确可见影响；更换执行人不改历史；已完成一次性事项不能直接改期、改为重复或换人；本人关闭提醒优先；邀请可转发并供多人主动加入。

本文描述目标能力。当前代码仍只有基础工程，实现状态见 [SCOPE.md](SCOPE.md)；接口、数据结构与具体交互见 [业务开发设计](business/DELIVERY.md)。

## 产品目标与场景

在一个个人工作台中记录、查看和处理自己及多个家庭的事情，减少遗忘，让家人能够协助并了解每次完成情况。

| 场景 | 首版支持的流程 |
| --- | --- |
| 爸妈容易忘记定期吃药，儿女帮助提醒 | 儿女代建周期事项，在小程序内查看到时提示，本人或获授权家人记录每人、每次的完成情况 |
| 临时记录明天的几件事情 | 输入标题、选择明天即可保存，按日期查看并逐项完成，无需强制设置具体时刻或提醒 |
| 孩子在爷爷奶奶家，每天有作业，爸妈查看进度 | 创建孩子的每日事项，爷爷奶奶代记完成，爸妈查看当天及历史进度、记录人和时间 |
| 同时管理与爸妈、与配偶孩子组成的两个家庭 | 待办与提醒跨家庭聚合，按每项原有权限直接操作，无需先切换家庭 |

吃药场景使用通用事项承载用户填写的安排，不增加药物剂量建议、疗程计算等医疗决策功能。

## 首版范围

- 基本家庭成员管理，支持一个真实用户同时加入多个家庭。
- 家庭内创建虚拟人，用于没有账号的孩子或老人。
- 个人及家庭待办的创建、编辑、完成、补记、撤销、跳过、删除和恢复。
- 一次性事项、每日或每周周期事项，同一天可设置多个时刻。
- 默认私密、指定家人可见、明确的代记与提醒权限。
- 列表多选后批量增加可见人，并支持个人事项批量选择家庭归属后共享。
- 跨家庭聚合的待办、到时提醒、完成操作与家人进度。
- 仅使用小程序内提醒，关闭后不主动发送微信通知、短信、电话或系统推送。

首版不包含聊天、积分排行榜、照片附件、复杂审批、外部日历同步、微信订阅消息或站外主动通知。

## 家庭、真实成员与虚拟人

### 家庭与成员

- 一个真实账号可创建或加入多个家庭；每个家庭拥有独立的成员关系、称呼和权限。
- 每个家庭有一名真实成员作为家庭拥有人，创建家庭的人默认成为拥有人；首版不另设多级管理员。
- 家庭拥有人管理家庭信息、邀请和成员，支持发出及撤销邀请、查看及移除成员；邀请由接收人主动接受，同一家庭重复接受不重复加入。
- 邀请有效期 7 天，可转发并供多人使用；持有有效邀请的人确认后即可加入，无额外审批。生成时明确提示“邀请可转发，持有者可加入”；撤销仅阻止后续加入，不移除已经加入的人，拥有人可另行移除成员。
- 其他真实成员可以创建并管理自己的事项，也可以主动退出家庭。
- 未加入家庭时仍可使用个人记事和提醒，需要共享给家人时再创建或加入家庭。
- 家庭称呼只用于展示，不能根据“爸爸”“奶奶”等称呼自动赋权。
- 在家庭 A 是拥有人，不代表在家庭 B 也有管理权。

### 虚拟人

- 家庭拥有人可在家庭中直接创建虚拟人，填写称呼等必要展示信息，代表没有独立账号的孩子或老人。
- 虚拟人属于具体家庭，不具备登录能力，不能自行接收提示、发起操作或承担家庭拥有人角色。
- **涉及虚拟人的事项，实际归属人为该家庭拥有人；界面上的执行对象、名称及进度展示为对应虚拟人。**
- 实际归属人、虚拟执行对象、真实创建人、完成记录人分别保存，不能把代建或代记操作记成虚拟人本人执行的系统操作。
- 提醒发送对象必须是实际使用小程序的真实成员；虚拟人事项启用提醒时，选择家庭拥有人或其他获授权家人接收。
- 虚拟人支持改名和停用；停用后不能选作新事项对象，历史事项仍保留对应身份和记录，未结束事项由家庭拥有人继续管理。
- 不自动合并不同家庭的同名虚拟人。首版不提供虚拟人绑定真实账号、自动认领、跨家庭迁移或账号合并。

示例：妈妈是家庭拥有人，爸爸创建“小宝每日作业”。事项实际归属妈妈，执行对象展示“小宝”，创建人保留爸爸；奶奶记录完成后，显示“小宝已完成，由奶奶记录”，不能显示成妈妈做了作业。

## 事项归属与权限

### 归属和参与人

| 概念 | 含义与规则 |
| --- | --- |
| 所属家庭 | 家庭事项归属一个家庭，周期各次继承该归属；个人事项可以暂不归属家庭 |
| 实际归属人 | 负责事项持续管理的真实用户；普通事项默认创建者，虚拟人事项为家庭拥有人，退出交接后为承接人 |
| 创建人 | 实际创建事项的真实用户；交接后也保留原创建记录 |
| 执行对象 | 实际要做事情的人，可以是本人、真实家人或虚拟人；每次安排只对应一个对象，周期换人不改写历史各次对象 |
| 可见人 | 被明确允许查看事项及其完成记录的真实家人 |
| 提醒对象 | 指定在小程序内看到该事项到时提示的真实用户 |
| 可代记家人 | 被明确允许替执行对象记录或撤销完成的真实家人 |

- 创建家庭事项时明确显示归属家庭。从某家庭视图新增可预填该家庭，保存前仍显示归属。
- 个人事项需要共享时，先明确选择一个家庭，再选择该家庭的可见人。
- 一个家庭事项不同时归属多个家庭，也不直接分享给只属于另一个家庭的成员；爷爷奶奶要参与孩子的作业事项，需要加入该事项所属家庭。
- 首版不提供已归属家庭的事项跨家庭迁移。切换筛选不会修改事项归属。
- 给爸爸和妈妈安排同一件事时分别创建事项，避免一个人的完成替代另一个人。

### 可见与管理

- 普通新建事项默认执行对象为自己，仅创建者自己可见，不默认勾选其他家人。
- 明确选择真实家人为执行人时，该家人自动具有必要查看及本人记录权限，无需接受安排；保存前明确提示“该家人将能查看并记录完成”。这不自动开启该家人的提醒，也不授予内容编辑或管理权限。
- 虚拟人事项实际归属家庭拥有人：拥有人具有查看和管理权限，真实创建人也可见并管理；创建时明确展示这一归属及可见范围，不默认向家庭全员公开。
- 在事项所属家庭保持有效成员关系的实际归属人和创建人，可编辑内容、删除、恢复、调整可见人和代记权限。
- 成员退出后不因保留“原创建人”记录而继续获得访问权；承接后的管理权按当前实际归属人判断。
- 执行人本人及可代记家人需有可见权限，才能记录或撤销本次完成；可见本身不授予编辑、代记或再次共享权限。
- 实际归属人及有效创建人也可记录完成，但必须保留真实操作身份，不将代记伪装成本人确认。
- 家庭拥有人身份不自动开放所有普通成员的私密事项；虚拟人归属事项及退出后承接的事项按实际管理关系授权。
- 提醒对象和可代记家人从事项所属家庭中有可见权限的真实成员选择；个人事项仅用于本人。
- 可见人可以管理自己是否接收该事项的提醒，不改变其他人的提醒设置；增加可见人不自动增加提醒对象或代记权限。
- 本人主动关闭提醒优先于管理者设置；管理者不能再次开启，只有本人主动开启才解除此限制。普通未勾选不等于本人主动关闭；限制按该用户与事项保留，取消后重新增加可见、成员重新加入或恢复事项不能绕过本人选择。
- 取消可见权限时同步撤销该人的提醒与代记权限，在保存前展示影响。事项实际归属人的管理权限不能通过取消普通可见人来撤销。
- 周期系列的可见性统一管理，覆盖历史与未来记录；与修改未来周期时间的规则分开处理。

## 成员退出与默认交接

- **成员退出或被移除后，需要承接的该家庭事项及管理职责默认交接给当前家庭拥有人，不要求逐项选择接收人。**
- 交接涵盖该成员实际归属的家庭事项，包括未完成事项、周期规则及历史记录的管理；已经归属家庭拥有人的虚拟人事项不重复转移。
- 该成员作为创建人保有的管理职责随退出终止，家庭拥有人承接需要保留的管理职责；其他有效成员已有的合法管理或查看权限保留。
- 不归属该家庭的个人事项以及其他家庭事项不参与交接。
- 退出界面明确展示默认承接人及交接范围，包括该家庭内原本仅本人可见、现需交接的事项；交接不等于向家庭全员公开。
- 交接不改写历史的创建人、执行对象、完成时间或操作人，也不重置完成状态或重新生成周期次数。
- 已退出成员不再接收该家庭提醒。其尚需履行的执行或协助安排由拥有人承接管理并重新安排，不能直接认定由拥有人实际做了原事项。
- 交接完成后退出成员失去该家庭事项的访问及操作权限，聚合列表、提醒和进度同步更新；其他家庭不受影响。
- 家庭拥有人退出前必须把家庭拥有权转交给另一名真实成员；虚拟人事项及其管理职责随家庭拥有权交给新拥有人，仍展示原虚拟人。
- 没有可承接的真实成员时，首版不允许家庭拥有人直接退出或移除自己；先邀请并转交。首版不提供家庭解散和全量数据销毁。

## 时间、周期与完成记录

### 一次性事项

- 标题必填，默认执行对象为自己；备注、计划日期、具体时刻均可选，小程序内提醒默认开启，可手动关闭。
- 输入标题、选择明天即可保存，支持连续新增多个独立事项，不强制填写提醒时刻。
- 日期事项不自动转换为午夜提醒；计划日期和提醒时间分别表达，不额外要求填写截止时间。
- 无日期事项放在“未安排”；有日期事项按今日、明日或指定日期查看。
- 超过计划日期的未完成事项保留原日期，不自动改期；已到提醒时间与计划日期已过分别提示。
- 一次性事项可提前完成，也可补记；保存已到提醒时间的未完成事项后，在下一次正常刷新时显示到时提示。

### 周期规则

- 支持每天、每周指定星期，可设置开始日期和可选结束日期；结束日期当天仍按规则安排。
- 每个选定日期可以没有具体时刻，或设置一个、多个时刻；无时刻时每个日期对应一次事项，有多个时刻时逐次独立记录。
- 每月、农历及复杂自定义间隔不纳入首版。
- 日期与周期计算采用 `Asia/Shanghai`，瞬时时间存储沿用项目 UTC RFC3339 毫秒格式。
- 每天、每个时刻对应独立完成记录。当天完成不影响次日，上午完成不影响晚上，一个人完成不影响另一人。
- 未使用小程序期间的应做记录仍可回看；上次未完成不阻止下次出现，不因上次完成晚了而改变周期。
- 新建有时刻的周期，从开始日期及创建时刻之后的有效计划时刻安排，不追补创建前的次数；无时刻且开始日期为今天时包含今天。
- 修改周期只影响尚未到时的未来记录，不覆盖已到时或已完成记录；首版不支持为未来周期次数提前完成，也不支持单独修改某一次的计划时刻。
- 支持跳过当前或历史某次，保留“已跳过”及操作记录，不算已完成，不改变下一次计划。
- 支持暂停、恢复及停止整个周期。暂停期间不产生应做记录，恢复从下一次有效计划继续，不补出暂停期间记录；无时刻规则恢复后从下一有效日期继续。
- 暂停或停止保留历史及此前未完成记录；完成本次不会结束整个系列。

### 编辑边界与执行人变更

- 未完成的一次性事项允许调整日期、时刻、执行对象或改成周期；已完成的一次性事项保留原安排，不直接改期、改成重复或换人，需要新安排时另建。已跳过事项需先撤销跳过再调整安排。标题、备注仍可按管理权限修改，操作历史保留。
- 周期更换执行人只影响尚未到时的未来安排；已到时、已完成及已跳过次数保留原执行人，历史进度与代记身份不重新归到新人。无时刻次数沿用日期边界，今天已存在的次数保留原执行人。
- 当前执行对象与历史各次执行对象分别展示；原执行人对保留次数的必要访问及本人记录能力仍按其有效成员关系判断，新执行人不因此取得代记旧执行人的权限。周期可见性仍统一管理，不将历史权限快照当作当前授权。
- 已有应做或操作历史的周期不能直接改为一次性；可以停止后另建一次性事项。每天与每周之间调整仍遵循只改未来、不覆盖历史的规则。

### 完成与变更

- 状态为待完成、已完成、已跳过；时间提示与完成状态分别表达。
- 历史没有完成记录，表示尚未确认，不推断现实中一定没有做。
- 记录实际完成时间、系统记录时间、真实记录人及可选备注；默认实际完成时间为当前时间，允许有权限的人补记历史。
- 支持撤销完成或跳过，回到待完成并保留变更记录；多人记录的是同一次共同结果，不要求所有可见人分别勾选。
- 不要求照片、审批或完成证明。
- “已完成 2/3 项”只计算当前视图有权查看的应做记录；已跳过单独显示并从应做分母排除，原始记录保留。

### 删除与恢复

- 删除一个事项、跳过一次、停止整个周期使用不同入口和文案。
- 对已有历史的周期优先提供“停止后续”，保留历史；删除整个事项时明确包含整个系列。
- 首版删除采用可恢复处理，不提供彻底删除或自动到期清理；删除后从正常列表、提醒和进度统计移除。
- 恢复时保留历史，重新校验成员及可见权限，不恢复已退出成员的访问权；周期以暂停状态恢复，由有管理权限的人选择继续，删除期间不补出新的周期次数。

## 小程序内提醒

- 新建事项默认开启创建者自己的小程序内提醒，可手动关闭；增加可见家人仍不自动增加提醒对象。
- 未填写具体时刻时保留开启状态，不产生到时提示，也不自动补成午夜；设置具体时刻后按该时刻提醒。
- 进入、返回前台及持续使用小程序时刷新到时事项；关闭后不主动通知，下次进入时补展示仍需处理的记录。
- 所有家庭中指定提醒当前用户的事项集中展示，标明家庭与执行对象；列表家庭筛选不暂停其他家庭的提醒。
- 每个提醒接收人的已读、收起状态独立；读过或收起只影响自己的展示，不完成事项、不隐藏其他人的提示。
- 一次提醒只对应当前次记录，下一周期次数有独立状态；未完成事项即使提示收起，仍可在待办和历史提醒中查看。
- 看过提示、已口头提醒家人与事项已完成分别理解；首版不额外记录“已口头提醒”，也不自动升级催办。
- 完成、跳过或删除后撤销对应次的待处理提示；修改未来计划时更新对应未来提示，撤销完成后按当前时间重新判断是否到时。
- 提醒设置保存成功不等于事情已完成。读取或保存失败明确提示并允许重试，不能展示成空列表或设置成功。

## 跨家庭聚合与批量操作

### 统一工作台

- 默认展示跨家庭的今日事项，区分自己要做、需要协助、共享给自己查看的内容；支持明日、未安排、未完成、已完成及日期查看。
- 已早于今天的未完成事项单独折叠并显示数量，避免周期积压淹没今天；顶部汇总当前用户的到时提醒。
- 支持家庭筛选，清除后恢复全部视图；家庭名称与执行对象明确展示，不仅靠颜色区分。
- 同一条记录同时匹配多个身份时只展示和统计一次；不同家庭的同名事项、不同周期次数保持独立。
- 完成、撤销、详情及编辑均可从聚合列表直接操作，按每项实际家庭和权限判断；只可见的事项没有完成权限。
- 从某个家庭筛选进入事项后，再改变筛选，不得让尚在进行的操作作用于另一个家庭。
- 聚合按当前用户权限读取，不能借共同成员关系向其他家人泄露另一个家庭的事项、成员或统计。
- 刷新部分失败时明确提示数据未完整加载，提供重试，不把缺失数据当作零项或全部完成。

### 批量增加可见人

- 列表支持选择自己有管理权限的多项事项，统一增加可见人。
- 每项保留原有名单，追加并去重；不覆盖原名单、不修改未选事项，不自动增加代记或提醒权限。
- 选中多个家庭的事项时按家庭分组，分别选择各组增加的成员，提交前显示事项数量及新增可见人。
- 同一人属于多个家庭时仍分别校验，不能把只属于家庭 A 的成员追加到家庭 B 的事项。
- 选中的未归属家庭的个人事项，支持一次明确选择目标家庭及可见人，再批量归属和共享；不根据筛选或其他选中项自动绑定家庭。
- 已归属家庭的事项仍留在原家庭，不能借个人事项批量归属入口迁移。
- 逐项返回结果，显示失败及原因，只重试失败项；单项的归属和可见人变更一并成功或失败，重复请求不重复追加。

## 页面范围

页面表达功能区域，不预设业务 tabBar。

| 页面或区域 | 内容 |
| --- | --- |
| 待办首页 | 跨家庭今日事项、到时提示、积压折叠、日期与状态筛选、批量选择 |
| 快速新增 | 标题、计划日期，保存后可连续记录下一件事 |
| 事项编辑 | 所属家庭、执行对象、周期和提醒；选择可见人后按人设置可代记与提醒 |
| 事项详情 | 当前次状态、来源家庭、执行对象、真实记录人、时间及周期历史，按权限提供操作 |
| 家人进度 | 按家庭、可见执行对象和日期查看；虚拟人显示自身名称，和其他家庭的同名对象区分 |

常规用户流程以事项和家人为中心。真实归属等信息只在涉及授权、虚拟人设置或交接等需要理解影响的位置明确展示。

## 验收场景

1. **周期照护**：爸爸、妈妈及每日多个时刻分别记录；父母或家人代记时保留真实操作人，已提醒不能直接视为完成。
2. **快速记事**：不建家庭、不填写时刻或提醒也能保存三项明日事项；可逐项完成，过期未完成不消失或改期。
3. **虚拟人作业**：非拥有人为虚拟孩子创建作业，实际归属家庭拥有人，界面展示孩子；奶奶代记后，爸妈看到孩子进度及奶奶的记录身份。
4. **默认私密与特例**：普通新事项仅创建者可见；虚拟人事项的实际拥有人和创建人按明确展示的范围可管理，其他家人无隐式访问权。
5. **查看与操作分离**：只可见者不能编辑、完成或共享；提醒、代记权限须有效可见，移除可见人后关联权限失效。
6. **退出交接**：普通成员退出或被移除后，相关家庭事项默认由拥有人承接，历史不改写、不重置状态；退出成员权限失效，其他家庭和个人事项保留。
7. **拥有权转交**：家庭拥有人先转交再退出，虚拟人事项实际归属更新到新拥有人，执行对象和历史保持；无真实承接人时不允许直接退出。
8. **周期例外**：跳过不算完成，暂停期间无应做次数，恢复从下一计划继续；修改未来计划、补记或撤销不覆盖其他次记录。
9. **提醒状态**：本人已读或收起不影响别人、不完成事项；关闭后不主动通知，返回时到时记录可见，下一次提醒状态独立。
10. **多家庭处理**：两个家庭的事项在同一首页与提醒区展示，可直接完成有权限的事项；筛选不影响另一家庭提醒，同名事项不误合并。
11. **批量追加**：不同家庭按组追加，原名单保留且去重；个人事项可批量明确归属并共享，失败项可单独重试，已归属事项不迁移。
12. **家庭隔离**：家庭 A 拥有人不能自动访问 B 的私密信息；聚合、详情、提醒及统计均校验，重复加入同一家庭不产生重复成员关系。
13. **删除恢复**：删除后列表和提醒移除，恢复保留历史且不恢复失效权限；周期暂停恢复，不补出删除期间次数。
14. **持久化与并发**：重新进入后数据保留；重复点击、请求重试不重复创建或交接，多人同时操作不静默覆盖修改；部分加载失败不能显示为零项。
15. **真实家人安排**：选择爸爸无需爸爸接受；保存前告知爸爸将可见并可记录，默认不开爸爸提醒，爸爸没有隐式管理权限。
16. **换人与改期**：周期换人后历史仍显示旧执行人，未来显示新人；已完成一次性事项不能直接改期、换人或转周期，已有历史的周期不能转一次性。
17. **本人提醒优先**：爸爸关闭后，创建者重新勾选、重新共享或恢复事项均不能开启爸爸提醒；只有爸爸主动开启才解除限制。
18. **转发邀请**：两人先后接受同一有效邀请均可加入；撤销后第三人不能加入，已加入的人仍保留成员关系。
19. **验证边界**：本地模拟、真实账号、真实云环境和真机验证分别记录，本地通过不能代替真实多成员联调。
