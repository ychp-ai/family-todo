# 小程序实现方案

当前已实现个人一次性待办与家庭协作原生页面。服务端及真实云验证范围见 [家庭协作](FAMILY.md)、[个人待办](PERSONAL.md)；周期、批量、按人进度和订阅提醒仍未实现。页面使用真实 API，不保留设计稿演示数据。视觉对应 `design/`，路由和产品规则见 [页面流程](../business/INTERACTIONS.md)。

## 服务与状态职责

| 模块 | 已实现职责 |
| --- | --- |
| `services/app-api-client.ts`、`identity-api.ts` | 统一信封、身份初始化及 unknown 响应校验 |
| `services/personal-api.ts` | 个人和家庭 action 的强类型调用、生成契约校验、10 秒超时、进程内未决写重试 |
| `services/family-api.ts` | 家庭列表、在用与停用虚拟成员分页、完整退出和转交影响预览 |
| `services/personal-lists.ts` | 列表追完游标、拒绝无游标未完成状态、丢弃最终失权或失败 scope 的条目 |
| `services/collaboration-draft.ts` | 执行对象映射、必要查看人、查看／代记／提醒独立草稿及本人关闭提醒保护 |
| `pages/*/index.ts` | 页面局部草稿、筛选、加载／空／错误／就绪状态、异步 epoch 与弹层 |

不引入大型状态库或业务 tabBar。共享契约运行时仅从小程序内 `shared/contracts.js` 引用；修改源契约后由构建生成，页面不访问数据库或直接调用 `wx.cloud`。

## 页面与导航

- 首页：全部家庭、仅个人和指定家庭筛选；按执行对象本人、代记能力分为“我来做／帮家人／关心一下”，显示真实记录人。提醒始终跨家庭读取。快速新增支持家庭、真实或无账号执行对象、查看人及默认只提醒自己。
- 家庭：家庭列表、创建与改名、本人及拥有人修改称呼、无账号成员添加／改名／停用。拥有人管理名单显式追完 active 和 inactive 两种分页，其他成员只读取可见在用名册。
- 邀请：拥有人创建、查看和撤销邀请；生成口令及路径由用户复制或主动分享。加入使用口令预览、填写称呼、明确点击接受三个步骤，不自动加入。
- 交接：转交仅选择其他在用真实成员；无承接人提示邀请。退出／移除及转交预览追到 complete 后才显示计数和确认按钮。拥有人先转交，之后单独确认退出。
- 完整编辑：家庭与执行对象、一次性日程、查看／代记／提醒三列矩阵。必要查看人依据创建管理者和当前执行对象重算并锁定；旧回执缺少创建管理者标记时先刷新再允许更换执行对象。取消查看同时确认撤销代记和提醒；本人关闭的提醒不能由其他人强开。个人事项可一次归属家庭，家庭事项不能迁移。已完成／跳过时锁定日程和执行对象，另建入口创建新事项。
- 详情：真实家庭、执行对象、管理人、查看人与代记人，操作分别遵循 canRecord／canEdit／canShare／canDelete。只显示当前用户自己的提醒设置。共享现有家庭事项使用 task.setAccess。
- 回收站：支持聚合与家庭筛选；仅 canRestore 条目提供恢复，成功后展示实际 removedParticipantCount。无法读取家庭时显示可重试错误，不伪装空列表。

所有页面使用原生 custom navigation、WXML 控件和 WXSS；卡片、编辑、权限矩阵与家庭交接弹层映射 `design/flows.*`，首页映射 `design/prototype.js` 与 `design/styles.css`。控件热区至少 44 CSS px。

## 身份、失权与异步响应

App 的 `globalData.session` 持有 `IdentitySession`。`ensure()` 合并并发身份初始化；启动仅初始化云能力，不主动请求身份或授权窗口。业务页面调用 readySession 后读取数据。UUID 使用 `wx.getRandomValues`，不降级到 Math.random；最低支持基础库仍需真机确认。

首页和详情在前台进入时刷新，可见期间 30 秒轮询，读取失败按 5／15／30 秒退避，隐藏停止。页面使用 epoch 忽略已切换家庭、日期、页面卸载后的旧响应。加载开始即撤下旧列表或详情；读取失败、失权时清理正文、权限行、历史和提醒，不能把旧数据当成当前授权。

首页列表收集器将最终非 ok scope 的旧分页条目移除，摘要为 null 时显示尚未完整加载，不补造总数。回收站无法完整读取时整体显示错误。跨家庭提醒与当前事项筛选独立，完成／跳过／删除后通过刷新取得新状态。

`task.update` 返回 `accessLost: true` 是保存成功：编辑页清空正文和权限，重新进入首页，不再读取该事项。权限拒绝时同样清理敏感编辑内容。版本冲突保留本地标题和备注；用户查看最新内容后，可保留这两项输入并重新取最新家庭名册、执行对象、日程和权限，再核对保存，避免覆盖其他人的提醒退出意愿。

## 未决写、预览与邀请口令

调用前生成 requestId 并克隆完整 action/payload。网络失败、超时及无法验证的响应作为结果未知，进程内保留原请求；重试发送同一个 requestId 和完整原 payload。确定成功或业务拒绝后释放。超时迟到响应不会提前释放未决请求。

统一服务跨页面保留未决请求，首页提供“重试确认”入口。存在未决请求时禁止开始不同参数的新写，防止用户修改草稿或重新预览后重复执行。退出／转交重试保留原 previewToken、版本与目标；PREVIEW_EXPIRED 明确提示重新查看影响。预览本身不完整时不显示最终计数，不允许确认。

邀请口令只在当前进程内存中使用，不写日志或本地存储；离开邀请页清除页面口令。需要重试的原接受请求仍由统一服务在内存中持有。生成口令用于用户主动复制与微信分享，标题不含口令；邀请有效期来自服务器。未决请求与草稿尚未跨进程持久化，小程序被终止后需要重新读取服务端状态，不能声称已实现离线队列。

## 验证与未覆盖范围

服务测试覆盖完整 payload／requestId 重试、不同写阻断、邀请 unknown guard、空页 continuation、重复游标、完整影响预览、active／inactive 管理名单，以及失败 scope 条目清理。权限草稿测试覆盖必要查看人、无账号执行对象、独立代记和提醒及本人关闭保护。

原生 Page 注册模拟验证切家庭乱序响应、提醒不受家庭筛选影响、普通查看者操作阻断、保存后合法失权与拒绝后的草稿清理。测试不替代真机验收。需要至少两个真实账号继续验证邀请加入、代记、移除／交接、微信分享、弱网未知结果重试、前后台切换、字体放大、键盘避让和不同屏幕安全区。

周期、批量共享、按人进度、订阅提醒、全局刷新协调器、跨进程未决队列与草稿恢复属于后续能力，当前入口不会伪造完成状态。
