# 小程序实现方案

当前已实现个人与家庭一次性／周期待办、家庭协作、按执行对象进度和批量追加可见人的原生页面。服务端及真实云验证范围见 [家庭协作](FAMILY.md)、[个人待办](PERSONAL.md)和发布记录；本地页面测试不代表真实云或真机验证。订阅提醒尚未实现。页面使用真实 API，不保留设计稿演示数据。视觉对应 `design/`，路由和产品规则见 [页面流程](../business/INTERACTIONS.md)。

## 服务与状态职责

| 模块 | 已实现职责 |

| `services/app-api-client.ts`、`identity-api.ts` | 统一信封、身份初始化及 unknown 响应校验 |
| `services/personal-api.ts` | 个人和家庭 action 的强类型调用、生成契约校验、10 秒超时、账号隔离的未决写恢复 |
| `services/family-api.ts` | 家庭列表、在用与停用虚拟成员分页、完整退出和转交影响预览 |
| `services/personal-lists.ts` | 列表追完游标、离开页面停止后续读取、游标过期重建一次快照、丢弃最终失权或失败 scope 的条目 |
| `services/collaboration-draft.ts` | 执行对象映射、必要查看人、查看／代记／提醒独立草稿及本人关闭提醒保护 |
| `services/schedule-draft.ts`、`editor-seed.ts` | 日程输入校验和兼容的进程内草稿交接 |
| `services/write-recovery.ts`、`input-recovery.ts` | 账号隔离的原请求与原始输入存储、完成标记、草稿所有权和恢复校验 |
| `services/batch-viewers.ts` | 按事项去重、显式家庭归属、逐组追加查看人及失败项版本刷新 |

## 页面与导航

- 首页：全部家庭、仅个人和指定家庭筛选；按执行对象本人、代记能力分为“我来做／帮家人／关心一下”，显示真实记录人。提醒始终跨家庭读取。快速新增支持家庭、真实或无账号执行对象、查看人及默认只提醒自己；高级区内联“不重复／每天”，每日要求开始日期并以服务端预览拒绝当天已过的所选时刻，支持保存并继续记。完整编辑入口保留草稿进入每周／多时刻安排。
- 家庭：家庭列表、创建与改名、本人及拥有人修改称呼、无账号成员添加／改名／停用。拥有人管理名单显式追完 active 和 inactive 两种分页，其他成员只读取可见在用名册。
- 邀请：拥有人创建、查看和撤销邀请；生成口令及路径由用户复制或主动分享。加入使用口令预览、填写称呼、明确点击接受三个步骤，不自动加入。
- 交接：转交仅选择其他在用真实成员；无承接人提示邀请。退出／移除及转交预览追到 complete 后才显示计数和确认按钮。拥有人先转交，之后单独确认退出。
- 完整编辑：家庭与执行对象、一次性／每日／每周日程、日期范围、每周日期、最多六个不同的时刻和服务端下一次预览，以及查看／代记／提醒三列矩阵。必要查看人依据创建管理者和当前执行对象重算并锁定；编辑周期时同时保留服务端标记的历史必要查看人；旧回执缺少创建管理者标记时先刷新再允许更换执行对象。取消查看同时确认撤销代记和提醒；本人关闭的提醒不能由其他人强开。个人事项可一次归属家庭，家庭事项不能迁移。已完成／跳过的一次性事项锁定日程和执行对象；完成后可另建，跳过提示先撤销。周期执行对象修改说明历史保留原人，是否允许转回一次性由服务端历史校验决定。
- 详情：真实家庭、执行对象、管理人、查看人与代记人，操作分别遵循 canRecord／canEdit／canShare／canDelete。只显示当前用户自己的提醒设置。共享现有家庭事项使用 task.setAccess。首页和提醒传递完整 OccurrenceRef，详情显示所选次数的历史执行对象和 canRecord；未来次数仍可查看但不能记录。周期详情按日期查询次数，并按 canEdit／canResume 提供暂停、继续、停止；继续前读取服务端预览，不补暂停期间。
- 回收站：支持聚合与家庭筛选；仅 canRestore 条目提供恢复，成功后展示实际 removedParticipantCount。无法读取家庭时显示可重试错误，不伪装空列表。恢复周期明确提示变为暂停，曾停止系列只恢复历史，canResume 为 false 时不展示继续入口。
- 家人进度：首页家人入口进入独立进度页，按家庭、执行对象及日期读取 progress.get；完整可见结果中的历史执行对象补入筛选，不扩大 family.get 名册。家庭管理仍在原路由。未完整结果保留 members=null 并续读；暂不可用保留游标供显式重试，过期则仅重建一次。只有完整结果才显示计数和进度环，空态说明可见范围。
- 批量追加：首页只选择可编辑且可共享的事项，相同事项多个次数按 taskId 去重，上限 20。按家庭分组，个人事项必须明确选择目标家庭；仅选择新增查看人，不添加代记或提醒。结果逐项显示成功／待确认／失败；待确认沿用原操作继续，全体结束后才允许重试失败项，并先读取其最新版本。

所有页面使用原生 custom navigation、WXML 控件和 WXSS；卡片、编辑、权限矩阵与家庭交接弹层映射 `design/flows.*`，首页映射 `design/prototype.js` 与 `design/styles.css`。控件热区至少 44 CSS px。

## 身份、失权与异步响应

App 的 `globalData.session` 持有 `IdentitySession`。`ensure()` 合并并发身份初始化；启动仅初始化云能力，不主动请求身份或授权窗口。业务页面调用 readySession 后读取数据。UUID 使用 `wx.getRandomValues`，不降级到 Math.random；最低支持基础库仍需真机确认。

首页和详情在前台进入时刷新，可见期间 30 秒轮询，读取失败按 5／15／30 秒退避，隐藏停止。页面使用 epoch 忽略已切换家庭、日期、页面卸载后的旧响应。加载开始即撤下旧列表或详情；读取失败、失权时清理正文、权限行、历史和提醒，不能把旧数据当成当前授权。

首页列表收集器将最终非 ok scope 的旧分页条目移除，摘要为 null 时显示尚未完整加载，不补造总数。回收站无法完整读取时整体显示错误。跨家庭提醒与当前事项筛选独立，完成／跳过／删除后通过刷新取得新状态。

`task.update` 返回 `accessLost: true` 是保存成功：编辑页清空正文和权限，重新进入首页，不再读取该事项。权限拒绝时同样清理敏感编辑内容。版本冲突保留本地标题和备注；用户查看最新内容后，可保留这两项输入并重新取最新家庭名册、执行对象、日程和权限，再核对保存，避免覆盖其他人的提醒退出意愿。

## 未决写、预览与邀请口令

调用前生成 requestId 并克隆完整 action/payload。业务写发送前先持久化原请求；网络失败、超时及无法验证的响应作为结果未知，退出重启后仍保留原请求；重试发送同一个 requestId 和完整原 payload。确定成功或业务拒绝后释放。批量成功信封若 complete=false 仍保留原请求；后续结果完全采用服务端当前返回，不合并旧成功版本，避免失权或预算回退时暴露旧结果。同一未决操作合并在途 Promise；超时迟到响应不会提前释放未决请求或覆盖新回执，已完成批量的继续入口不会新建写。

统一服务跨页面保留未决请求，首页提供“重试确认”入口。存在未决请求时禁止开始不同参数的新写，防止用户修改草稿或重新预览后重复执行。退出／转交重试保留原 previewToken、版本与目标；PREVIEW_EXPIRED 明确提示重新查看影响。预览本身不完整时不显示最终计数，不允许确认。

邀请口令只在当前进程内存中使用，不写日志或本地存储；离开邀请页清除页面口令。需要重试的原接受请求仍由统一服务在内存中持有。生成口令用于用户主动复制与微信分享，标题不含口令；邀请有效期来自服务器。其他可恢复写按云环境与可信应用账号隔离，恢复前校验存储结构、action 白名单与 payload；存储失败阻止新写并提示重试。不持久化 API 响应，不在启动或网络恢复时自动重放。

## 验证与未覆盖范围

服务测试覆盖完整 payload／requestId 重试、不同写阻断、邀请 unknown guard、空页 continuation、重复游标、完整影响预览、active／inactive 管理名单，以及失败 scope 条目清理。权限草稿测试覆盖必要查看人、无账号执行对象、独立代记和提醒及本人关闭保护。

原生 Page 注册模拟验证切家庭乱序响应、提醒不受家庭筛选影响、普通查看者操作阻断、保存后合法失权与拒绝后的草稿清理。测试不替代真机验收。需要至少两个真实账号继续验证邀请加入、代记、移除／交接、微信分享、弱网未知结果重试、前后台切换、字体放大、键盘避让和不同屏幕安全区。

周期服务／Page 测试另覆盖日程输入错误、当前与历史次数准确定位、未来次数禁止记录、编辑预览乱序和失权、停止后恢复不可继续、未完整进度与过期游标、家庭／日期切换忽略旧响应、批量同 ID 完整原请求续跑、超时迟到响应、失败子集刷新版本和切换范围清除批量草稿。

未决业务写和编辑/快速新增草稿已支持跨进程主动恢复；完整规则与验证见 [异常恢复](RECOVERY.md)。订阅提醒、全局刷新协调器仍属于后续能力。原生开发者工具编译及真实云操作记录应以本轮验收报告和发布记录为准。
