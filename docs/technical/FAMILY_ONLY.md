# 家庭必选与历史个人事项迁移

## 当前规则

2026-09-15 用户要求移除个人事项，所有新任务必须在创建或加入家庭后创建。快速新增、完整编辑和服务端统一新建入口落实该规则；默认私密、执行对象、可见人、代记及提醒权限保持现有规则。

无家庭时引导创建或加入；有家庭时选择有效的上次偏好、当前家庭筛选或首个可访问家庭。保存前展示所属家庭。旧个人新建草稿恢复时使用有效家庭，原执行对象不可用则提示重新核对。家庭列表读取失败仍显示错误，不当作无家庭处理。

## 历史数据与迁移

用户选择将已有个人事项迁入指定家庭，但尚未提供目标家庭及账号范围。因此本次未运行云端迁移，也未删除、隐藏或自动归属历史数据。

获得目标后，先在可信登录身份下核对家庭 ID 和有效成员资格，读取该账号的个人事项并列出迁移范围。活动事项沿用 `task.batchAddViewers`：每批最多 20 项，提供 `taskId`、`expectedVersion`、`targetFamilyId` 和空 `viewerMembershipIds`，不额外向家人公开。暂停事项也需纳入清单，周期迁移限制以实际接口校验结果为准。

迁移保留事项 ID、历史、完成状态、日程和本人关闭提醒选择。未完成批次使用原 requestId 及完整参数续办，失败项明确记录；全部终态后才以新请求重试失败项。完成后读回确认所属家庭及状态。

回收站事项无法通过当前批量接口直接迁移，不能为迁移而自动恢复；需先核对实际数据，再制定保留删除状态的迁移处理。不同账号只能在各自可信身份下处理自己的个人事项，不能伪造调用上下文。
