# 异常恢复

本轮补齐小程序退出和重启后的未决写与编辑输入恢复。恢复不会主动执行写入；用户确认后仍由现有 API、权限检查、版本检查和持久化回执决定结果。不新增 action、集合或云端部署。

## 未确认的操作

客户端发送业务写入前保存原 action、requestId 和完整 payload。断网、10 秒超时、响应无法通过契约校验时，首页保留“重试确认”入口；确认请求沿用原参数和 ID。批量尚未 complete 时继续发送完整原批次，由服务端返回当前可见结果。

恢复数据按云环境和经服务端确认的应用账号隔离。缓存不是授权依据，重试仍会重新经过服务端鉴权。确定成功或明确业务拒绝后结束操作；结果尚未明确时不能改参数开始另一笔写入。损坏的未决记录会保留并阻止新写，不提供可能重复执行的“丢弃后重发”；若持续无法读取，需要人工核对服务端结果后处理。

邀请接受请求中的口令仅保留在当前进程内存，不能写入本地存储；关闭小程序后需要重新通过邀请入口预览并确认加入。生成邀请的响应口令也不持久化。退出与转交恢复保留原预览 token 和版本；预览过期时重新查看影响，不自动用新的承接人提交。

## 输入与草稿

草稿保存用户尚未提交的原始输入，包括空标题和未填完的日程；不能保存一份旧名册或权限 DTO 后当作有效授权恢复。完整编辑按事项 ID 和分享模式定位草稿；快速新增转完整编辑共用一份草稿和 UUID。日期按绝对日期保存，跨天恢复不自动改成今天。恢复前重新读取目标事项和家庭；失权后清理相关敏感输入。恢复不保留草稿中的代记和他人提醒勾选，会明确提示按最新设置重新核对；本人关闭提醒优先。已有事项发生版本变动时，沿用“查看最新内容 → 保留标题和备注并重新核对”的显式合并流程，不自动以新版本覆盖家人的修改。

草稿与保存请求关联；确认保存成功后删除对应草稿，页面已经卸载也不能留下可再次新建的同一份输入。结果未知时先确认原保存，不能把同一份草稿变成新的 task.create。

## 验收矩阵

| 情况 | 必须满足的恢复行为 |
| --- | --- |
| 写前本地保存失败 | 不发送新业务写；明确告知无法保存恢复信息 |
| 云端成功、客户端丢响应 | 重建服务实例后仍以原 requestId 查询回执，不重复业务写 |
| 批量部分完成后重启 | 恢复完整原批次，当前结果取自服务端 |
| 清理恢复记录失败 | 不换 ID 再发同一业务操作，不误报已经清理 |
| 恢复记录损坏 | 校验失败明确显示，不能当作无未决操作继续新写 |
| 账号/环境切换 | 不读取、展示或重放另一账号/环境的恢复内容 |
| 原请求迟到 | 不清除新账号或新一笔请求的状态 |
| 未填完的编辑输入 | 可以保留半填日程，恢复后仍经过正常输入校验 |
| 未知保存后重启 | 先确认原请求，已成功则清理草稿，不再次新建 |
| 版本冲突 | 保留输入，查看最新内容后显式合并 |
| 家庭失权或成员失效 | 重新鉴权、撤下编辑入口，不恢复旧授权或悄悄改为个人事项 |

### 开发者工具重启差异定位（2026-09-14）

已将应用草稿与独立存储探针分开验证：全新字符串及对象经 `wx.setStorageSync` 写入后可立即读回，但约 2 秒后 CLI `close → auto` 会丢失；等待 35 秒再关闭可读回同一唯一标记。只读核对本机微信开发者工具 RC 2.02.2608031 的存储实现，`persist` 会清除旧 timer，在最后一次写入 10 秒后调用 `saveImmediate`；关闭保存钩子排除了 Electron 分支。这解释了“较早写入可恢复，新写入失败”的差异，不属于草稿校验或账号隔离逻辑删除。

将验收脚本的关闭前等待明确设为 35 秒后，完整项目重开（另以 App 内存标记消失校验）通过：空标题、备注、未完整时刻恢复；放弃清理；quick→editor 共用草稿；真实创建成功后受控丢响应，重开再确认仍使用原 requestId/payload，事项 version=1，二次确认不发写，成功后不再恢复旧草稿。见 [本次原生验收](../verification/native-acceptance/README.md)。

该等待仅为当前开发工具的验收条件，未加入产品逻辑，未调用私有刷盘 API，未修改开发工具。即时关闭开发工具仍可能丢失未落盘内容；不能据此推断 iOS/Android 真机表现，真机进程终止与系统回收仍需独立验收。
