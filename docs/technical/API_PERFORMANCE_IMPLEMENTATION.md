## 观测开关

2026-09-16 本地新增（尚未部署）：设置 `FAMILY_TODO_PERFORMANCE_DETAILS=true`，且同时开启下述日志开关，可按固定的 19 个集合及读/写/查询分类计数，未知集合统一记为 `other`。新增 `databaseWaitCumulativeMs` 是各数据库操作耗时之和，并行等待会重叠，不能从总耗时中减去它推算 CPU 时间；`serializationMs` 是观测响应序列化的耗时。细分默认关闭。

将导出的 JSON 行日志传给 `node tools/summarize-api-performance.mjs <日志文件>`（或标准输入），可按 action 汇总调用量、错误、p50/p95、读写查询和响应字节，按应用层数据库操作总数排序。汇总不输出 requestId；它不替代平台计费和完整客户端分页链路统计。

服务端设置 `FAMILY_TODO_PERFORMANCE_LOGS=true` 后启用 `api.performance` 单请求日志，默认关闭。日志仅记录已知 action、requestId、结果/错误码和聚合计数，不记录 OpenID、查询条件、事项内容、邀请口令或 payload。日志输出失败不改变已经提交的响应。计数通过 AsyncLocalStorage 隔离并发请求，事务缓存命中不增加物理读取计数。

小程序逻辑列表观测同样默认关闭；未调用 `configureListMetrics` 时不抽样、不生成 operationId、不安装 requestId 观察器、不序列化或写日志。需要在受控验证版本启用时，在小程序启动代码显式配置，例如：

```ts
import { configureListMetrics } from "./services/list-metrics";

configureListMetrics({
  sampleRate: 0.01,
  sink: record => console.info(JSON.stringify(record)),
});
```

`sampleRate` 必须在 0 到 1 之间；调用 `configureListMetrics(null)` 可恢复关闭状态。采样在一次逻辑加载开始时决定，首页一次 refresh 使用一个 `home.refresh` 父操作及 family/task/reminder 三个显式子操作，不在模块中保存可串线的当前操作。首页父操作未命中采样时，三个子操作沿用该决定，不再次抽样。operationId 的异步生成不在业务请求派发路径上等待；配置本身是公开客户端配置，不得放入密钥、账号或环境凭证；sink 失败不会改变列表结果。

客户端记录只有固定 action/source/result/error、随机 operationId/requestId、页数、重启数、事项或成员计数和耗时，不记录标题、备注、用户、家庭、执行对象、筛选、游标、原始错误或 payload。`rpcCumulativeMs` 是客户端请求往返累计值，并行时可大于 `wallClockMs`。进度的 `continuationPages` 表示 `members=null` 的未完成响应，不把它记成空列表。完整内存缓存命中是 `cache` 且零 RPC；条件校验复用是 `unchanged` 且一条 RPC；无本地快照却收到 unchanged 时的无条件重取是 `no-cache-fallback`。取消记录为 `complete:false`，并等待已经启动的逻辑列表结束或取消后再输出其全部已发请求的真实 requestId 和累计时间；父操作同样等待已启动的子列表完成，不会因另一个子列表先失败而截断后续分页观测。

每个逻辑操作最多保留 256 个 requestId 关联；这只限制观测内存，不截断业务分页。超过上限后 `requestLinksComplete:false` 且 `droppedRequestLinks` 增加。子诊断 ID 生成失败或返回空值时，业务请求和结果不受影响；父记录通过 `missingChildOperationIds` 保留缺失子链数量，并设置 `requestLinksComplete:false`。将客户端与服务端 JSON 行放入同一文件后运行 `node tools/summarize-api-performance.mjs --logical-lists <日志文件>`，工具按 requestId 离线连接。父操作的 join 合并其子操作 requestId；子记录缺失或子诊断 ID 缺失时增加 `missingLogicalRecords`，不声称父链完整。每个 operation 的 `serverJoin` 保留匹配数、缺失数；`physicalTotals` 再按 requestId 全局去重，避免合并请求被多个逻辑消费者重复计费。缺服务端日志、缺子记录、缺子诊断 ID 或客户端关联被截断时 `complete:false`；完全没有匹配日志时 `functionCumulativeMs:null`，不能解释成零函数时间。该累计值只是 `api.performance.durationMs` 之和，不是平台 billed duration、冷启动总时长或 GB-s，后者须使用平台记录。未加 `--logical-lists` 的原 action 汇总格式保持不变；旧日志没有 `missingChildOperationIds` 时按 0 读取。

总耗时包含该 handler 的数据库调用，但不代表微信客户端端到端延迟；没有日志的超时请求也需要平台指标识别。指标不能替代真实云端验收。

## 会话清理

工具：`tools/cleanup-query-sessions.mjs`，使用固定版本 `@cloudbase/node-sdk` 开发依赖，不增加函数运行时依赖。

- 从安全环境变量提供已核验的 `TCB_ENV_ID`、`TENCENTCLOUD_SECRETID`、`TENCENTCLOUD_SECRETKEY`；临时凭证可提供 `TENCENTCLOUD_SESSIONTOKEN`。不要写入小程序配置或命令行文本。
- `node tools/cleanup-query-sessions.mjs` 只查询和汇总；加 `--apply` 才删除。可用 `--max-rows 1000` 调整单批上限（最大 10000），`--grace-ms` 不得小于一天。
- 仅处理 `query_sessions` 中 schemaVersion 1/2 且 expiresAt 早于固定 cutoff 的记录；按 `expiresAt,_id` 升序扫描并且只读取 `_id,schemaVersion,expiresAt`。每次默认最多扫描 1000 行。
- 删除时再次匹配 ID、schemaVersion、expiresAt，防止扫描后被替换的记录被删除；未知 schema 跳过。输出只有环境和汇总计数。
- `complete:false` 表示本批到达上限，并非已清理完；把结果中的 `checkpoint` 原样传给下一次 `--after TOKEN`。令牌只含固定 cutoff 和复合扫描位置，不含环境、账号或凭证；续跑沿用原 cutoff，未知 schema 也会推进位置，避免阻塞后续行。`complete:true` 后不要再复用该令牌；令牌校验失败时重新 dry-run，不能手工改写。
- 每批记录 `cutoff/scanned/eligible/skipped/deleted/complete`，并按每日新增会话数、宽限窗口及平均文档大小估算稳态容量；同时计入每行扫描读取和实际删除写入。未知 schema 数量增加时先调查，不能扩大删除范围。定期执行需要运维另行安排，本次没有创建定时任务或运行生产清理。

## 不可变排序分页：2026-09-16 本地验证

普通 occurrence 输出使用 scan / merge / output 检查点；小窗口最多 50 条且 JSON UTF-8 不超过 64 KiB，在内存完成排序，不写 run。更大窗口以固定四路归并成升序单链，最终续页仅读当前块及跨越块，不在每次恢复时重新加载所有 run 头。每轮按输入方向消费、逆序并前插输出块，保证旧块不可变；降序最终流通过单路反转归一为升序。manifest 每页 16 个 run 描述符，检查点最多四个输入位置和一个有界输出缓冲，软上限 96 KiB，存储硬上限仍为 128 KiB；字节包含中文、补充平面字符和 JSON 转义膨胀。

源扫描沿用 180 工作单位；归并/输出单请求最多约 48 次会话操作，所有阶段共享现有 8 秒截止并在剩余 4 秒停止常规工作，保留最终事务校验余量。在途 SDK 调用仍不可取消。窗口跳跃和进度直接聚合不变。旧 occurrence 游标显式 CURSOR_EXPIRED；失败/重放新写块都是新随机键，与源会话同 expiresAt，由 F1 清理，不覆盖原检查点。
