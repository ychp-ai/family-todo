## 观测开关

服务端设置 `FAMILY_TODO_PERFORMANCE_LOGS=true` 后启用 `api.performance` 单请求日志，默认关闭。日志仅记录已知 action、requestId、结果/错误码和聚合计数，不记录 OpenID、查询条件、事项内容、邀请口令或 payload。日志输出失败不改变已经提交的响应。计数通过 AsyncLocalStorage 隔离并发请求，事务缓存命中不增加物理读取计数。

总耗时包含该 handler 的数据库调用，但不代表微信客户端端到端延迟；没有日志的超时请求也需要平台指标识别。指标不能替代真实云端验收。

## 索引与上线顺序

1. 核对目标环境、数据库和现有索引，使用 `node tools/migration/provision-performance.mjs` 查看三个性能索引的增量计划；通过 `TCB_CLI` 和 `TCB_DATABASE` 指定已核验的 CLI 与数据库。
2. 本次已获部署授权，执行 `--apply` 创建 `task_segment_window(taskId,effectiveUntil,effectiveFrom,listOrder)`、`task_segment_previous_end(taskId,effectiveUntil)`、`session_expiry(expiresAt,_id)` 并回读核验。新证据保存在 `database/performance-provision-result.json`，历史迁移记录未覆盖。实际查询计划仍需验证，不宣称索引必然消除扫描。
3. 发布函数后，在隔离数据上验证历史片段、一次性改周期、分页重放、权限变更、提醒关闭、并发冲突和未知提交状态；开启观测比较同数据集读写数和延迟分位。
4. 无需批量回填旧事项。先发布支持 `view:"summary"` 的服务端，再发布请求精简列表的小程序；旧客户端不传该字段时仍返回完整 DTO。若回滚服务端，必须保留这个新增请求字段的兼容能力，或先将客户端切回完整请求。列表指纹包含 view，切换表示会使原游标失效；客户端走已有重新加载流程。暂存会话等待过期，不要删除业务回执。

## 会话清理

工具：`tools/cleanup-query-sessions.mjs`，使用固定版本 `@cloudbase/node-sdk` 开发依赖，不增加函数运行时依赖。

- 从安全环境变量提供已核验的 `TCB_ENV_ID`、`TENCENTCLOUD_SECRETID`、`TENCENTCLOUD_SECRETKEY`；临时凭证可提供 `TENCENTCLOUD_SESSIONTOKEN`。不要写入小程序配置或命令行文本。
- `node tools/cleanup-query-sessions.mjs` 只查询和汇总；加 `--apply` 才删除。
- 仅处理 `query_sessions` 中 schemaVersion 1/2 且 expiresAt 早于当前时间一天的记录；每次最多扫描 1000 行。
- 删除时再次匹配 ID、schemaVersion、expiresAt，防止扫描后被替换的记录被删除；未知 schema 跳过。输出只有环境和汇总计数。
- `complete:false` 表示本批到达上限，并非已清理完；未知 schema 大量堆积应先调查，不能扩大删除范围。定期执行需要运维另行安排，本次没有创建定时任务。
